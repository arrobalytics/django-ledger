# Contribution Guidelines for Django Ledger

> **⚠️ CLA REQUIRED BEFORE YOU SUBMIT A PULL REQUEST**
>
> By submitting any contribution to Django Ledger, you agree to the Contributor License Agreement (CLA) in
> [section 2](#2-contributor-license-agreement-cla) below. The CLA permits the project owner to license your
> contribution under GPL-3.0 **and** under commercial or proprietary terms. You keep your copyright. Please read it
> before opening a pull request.

Thank you for your interest in contributing to Django Ledger. Please read these guidelines before submitting a pull
request or other contribution.

All pull requests are welcome when they address bug fixes, enhancements, new ideas, or otherwise add value to the
project. Please refrain from pull requests that focus solely on linting, auto-generated code, cosmetic refactoring, or
similar non-value-add changes.

## 1. Dual-Licensing Disclosure

Django Ledger is currently licensed under the GNU General Public License version 3 (GPL-3.0). We want to be transparent
with our contributors about the project's licensing plans:

- **0.9.0 is a transition series.** The 0.9.x releases are a transitional series in which Django Ledger prepares to
  offer dual licensing: GPL-3.0 for open-source use, and a commercial license. Starting with 1.0, Django Ledger will be
  a dual-licensed project.
- **Review of existing contributions.** To enable this, existing third-party contributions will be reviewed and, where
  necessary, reimplemented by the project owner, so that the 1.0 release is fully controlled by the project owner or
  covered by the updated CLA.
- **Earlier versions.** Previously released versions remain available under GPL-3.0.
- **New contributions.** Contributions accepted from 0.9.0 onward are subject to the updated CLA below, which permits
  dual licensing starting with 1.0.

We value and appreciate every contribution made to the project to date.

## 4. Code Contributions

- Follow the project's coding standards and style.
- Include tests with new behavior or bug fixes whenever practical.
- Update documentation when behavior or public APIs change.

## 5. Pull Requests

- Open pull requests against the `dev` branch.
- Describe the problem and the solution clearly.
- Reference related issue numbers when they exist.
- Do not submit a pull request until you have read and agreed to the CLA in section 2.

## 6. Issue Reporting

- Use the issue tracker for bugs and enhancement ideas.
- Include enough detail to reproduce a bug, including versions and steps.

## 7. Project Authority

The project owner may use, modify, and distribute accepted contributions as part of Django Ledger, subject to the CLA,
and may reject any contribution.

## 8. Code of Conduct

Follow the project's Code of Conduct in all project spaces.
